# Дизайн: первичное LLM-ревью ADR/RFC

Дата: 2026-08-19. Статус: принят, реализован скелет.

## Проблема

Архитектор ревьюит ADR/RFC от разработчиков/аналитиков/продактов. Качество входящих
документов низкое: типовые дыры (нет класса критичности, один вариант «решения», нет TCO)
съедают время ревью до того, как доходит до содержательных вопросов.

## Решение

Промпт-пакет поверх корпоративного CLI (qwen3.5-397b, headless-режим, файлы-агенты,
MCP Confluence). Никакого своего сервера и оркестратора: bash-обёртка + jq. Локальная
модель не используется (решение от 2026-08-19: только корп-облако).

Три актива, переживающие любую смену транспорта:

1. **Рубрика** (`rubric/rubric.yaml`) — чек-лист как данные: id, вопрос,
   severity (blocker/question/nit), evidence, применимость, ссылки на нормы, hints для поиска.
2. **Нормативная база** (`norms/`) — md-выгрузки стабильного ядра корп-доки (классы
   критичности NFR, требования ИБ, каталог T-Lego) + `INDEX.md` с page-id и датами.
   Разбросанный хвост не выгружается — живой MCP-поиск на этапе 3.
3. **Промпт-конвейер** (`agents/reviewer.md` + `prompts/stage*.md`).

## Конвейер (`bin/review.sh <url>`)

| Этап | Кто | Вход → Выход | Суть |
|---|---|---|---|
| 1 | CLI+MCP | url → `adr.md` | достать страницу, нормализовать в markdown |
| 2 | CLI | рубрика+adr → `verdicts.json` | вердикт по каждому пункту; `pass` только с дословной цитатой |
| 3 | CLI+MCP | вердикты+adr+normy → `substance.json` | сверка с нормами: NFR vs класс, контрагенты, T-Lego, санити TCO |
| 4 | jq | json'ы → `report.md` | блокеры, таблица, цитаты, находки, вопросы автору |

Артефакты в `workspace/<slug>/` (gitignore), включая отправленные промпты; этапы
перезапускаются по одному (`--stage N`), готовые пропускаются, `--force` — с нуля.
JSON-выходы валидируются jq, невалидные роняют прогон с указанием файла.

## Анти-галлюцинации

- `pass` без дословной цитаты запрещён промптом; отчёт печатает цитаты-основания.
- Догадка = `unclear` + вопрос автору, не додумывать.
- Этап 3 ссылается только на реально открытые страницы; «не нашёл» — валидный результат
  с `confidence: low`.
- Отчёт подписан «сгенерировано LLM, проверь перед отправкой» — выход читает архитектор,
  не автор.

## Калибровка и критерий успеха

Golden set: 2–3 старых ADR с уже сделанным человеческим ревью; расхождения — в `feedback/`
(пропуски → рубрика, враньё → промпты). Инструмент готов, когда на новом ADR находит ≥80%
замечаний архитектора и не тащит мусор.

## Эволюция

- **Гейт**: `agents/selfcheck.md` («проверь себя до подачи») поверх той же рубрики —
  отдать авторам, когда рубрика докажет себя.
- **Транспорт**: при раскопанном OpenAI-совместимом API обёртка меняется на прямые вызовы;
  рубрика/нормы/промпты переезжают как есть.
