# Этап 3: содержательный проход

Рубрика пройдена (вердикты ниже). Теперь — проверка не «есть ли раздел», а «правда ли то,
что в нём написано». Работай только по пунктам, где в ADR есть за что зацепиться
(status `pass` или `unclear`); дыры этап 2 уже зафиксировал.

Что проверять (в порядке приоритета):

1. **NFR против класса критичности.** Прочитай `norms/nfr-classes.md`. Соответствуют ли
   заявленные availability/RTO/RPO классу, который указал автор? Если класс не указан —
   пропусти, это уже блокер этапа 2.
2. **Интеграции против реальности.** Для каждой системы-контрагента поищи через MCP
   Confluence её паспорт/класс критичности/SLA (см. `hints` в рубрике). Зависимость более
   критичного решения от менее критичной системы — находка. Не нашёл страницу — так и
   зафиксируй: «данных о системе X в Confluence не нашёл» с `confidence: low`.
3. **Lego.** Прочитай `norms/lego.md` и поищи в Confluence готовые компоненты под то,
   что автор собрался писать сам. Нашёл кандидата — находка с ссылкой.
4. **Санити TCO и эффекта.** Числа противоречат друг другу или здравому смыслу
   (нагрузка из раздела Scalability не бьётся с размером инфры, эффект не покрывает
   стоимость) — находка.

Правила: ссылайся только на страницы, которые реально открыл; каждая находка — с источником;
не нашёл ничего по пункту — не выдумывай находку.

Ответ — один JSON-документ без обёртки:

```
{
  "findings": [
    {
      "rubric_id": "<id пункта рубрики, к которому относится>",
      "finding": "<суть находки, одно-три предложения>",
      "evidence_source": "<файл norms/ или название+URL страницы Confluence, или пустая строка>",
      "confidence": "high | medium | low",
      "question_for_author": "<готовый вопрос автору или пустая строка>"
    }
  ]
}
```

Находок нет — верни `{"findings": []}`, это нормальный результат.
