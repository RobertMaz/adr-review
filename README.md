# adr-review

Первичное LLM-ревью ADR/RFC поверх корпоративного CLI (qwen3.5-397b + MCP Confluence).
Идея: рубрика и нормативная база — здесь, мозги — в корп-облаке, отчёт — тебе в файл.
Дизайн: `docs/2026-08-19-adr-review-design.md`.

## Запуск

```bash
./bin/review.sh https://confluence.example.com/pages/.../ADR-123
# → workspace/adr-123/report.md
```

Перегнать один этап после правки промпта: `--stage 2`; всё с нуля: `--force`.
Артефакты этапов (включая реально отправленные промпты) лежат в `workspace/<slug>/`.

## Перед первым запуском

1. **Подключи корп-CLI**: в `bin/review.sh` один FIXME-блок сверху — имя бинаря
   (или env `ADR_REVIEW_CLI`) и флаги headless-запуска + подключения файла-агента
   `agents/reviewer.md`. Больше скрипт про CLI ничего не знает.
2. **Заполни нормативную базу**: три файла в `norms/` — это заглушки с описанием того,
   что в них выгрузить из Confluence. Учёт — в `norms/INDEX.md`.
3. Нужен `jq`.

## Как это работает

Шесть этапов, каждый пишет артефакт в `workspace/<slug>/`:

1. **Нормализация** — CLI тянет страницу через MCP → `adr.md`.
2. **Рубрика** (`rubric/rubric.yaml`) — вердикт `pass/fail/unclear/n-a` по каждому пункту,
   `pass` только с дословной цитатой → `verdicts.json`.
3. **Содержательный проход** — сверка с `norms/` + живой MCP-поиск (классы критичности
   контрагентов, Lego, санити TCO) → `substance.json`.
4. **Проверка на неосмысленную генерацию** — маркеры AI-дичи (противоречия, гладкая
   пустота, сущности из ниоткуда) + 5–7 вопросов на понимание для устного разговора
   с автором → `slop.json`. Писать с AI можно; не понимать написанное — нельзя.
5. **Абстрактный промпт задачи** — обезличенная задача из ADR (без корп-названий и без
   подсказки решения) как готовый вопрос для корп web-LLM → `task-prompt.md`;
   независимый best-practice-ответ сравниваешь с решением команды.
6. **Отчёт** — чистый jq, без LLM → `report.md`: блокеры, таблица по рубрике, цитаты,
   находки, маркеры генерации, вопросы на понимание и готовые вопросы автору
   под копипаст в Confluence.

## Калибровка

После каждого реального ревью — файл в `feedback/` по `feedback/TEMPLATE.md`:
что LLM пропустила (дыра в рубрике), что наврала (дыра в промпте). Первая проверка —
прогнать 2–3 старых ADR, по которым ревью уже было, и сравнить со своими замечаниями.

## Правки

- **Что проверяем** — только `rubric/rubric.yaml`; id пунктов не переименовывать
  (на них ссылаются feedback и substance.json).
- **Как проверяем** — `agents/reviewer.md` (роль и железные правила) и `prompts/stage*.md`.
- **Против чего проверяем** — `norms/`.

Когда рубрика дозреет — добавить `agents/selfcheck.md` с тоном «проверь себя до подачи»
и отдать конвейер авторам как гейт; рубрика и нормы общие.
