# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Первичное LLM-ревью ADR/RFC поверх корпоративного CLI (qwen3.5-397b + MCP Confluence).
Кода почти нет: один bash-скрипт + jq; всё остальное — данные (рубрика, нормы) и промпты.
Дизайн и обоснования решений: `docs/2026-08-19-adr-review-design.md`.

## Запуск

```bash
./bin/review.sh <confluence-url>            # полный прогон; готовые этапы пропускаются
./bin/review.sh <url> --stage 2             # перегнать только этап 2 (после правки промпта)
./bin/review.sh <url> --force               # всё с нуля
```

Тестов и сборки нет. Проверка правок в скрипте — `bash -n bin/review.sh` и реальный прогон.
Зависимости: `jq` и корп-CLI (не подключён: FIXME-блок сверху `bin/review.sh` — имя бинаря
через env `ADR_REVIEW_CLI` и флаги headless-запуска в `run_llm()`; больше скрипт про CLI
ничего не знает).

## Архитектура: конвейер из шести этапов

`bin/review.sh` гоняет этапы 1–5 через LLM (один вызов `run_llm` на этап), этап 6 — чистый jq.
Каждый этап: шаблон `prompts/stageN-*.md` → подстановка плейсхолдеров (`{{ADR}}`, `{{RUBRIC}}`,
`{{VERDICTS}}`, `{{ADR_URL}}`) через awk/sed → отправленный промпт сохраняется как
`workspace/<slug>/prompt-stageN.md` → ответ становится артефактом этапа:

| Этап | Выход | Суть |
|---|---|---|
| 1 | `adr.md` | достать страницу через MCP, нормализовать в markdown |
| 2 | `verdicts.json` | вердикт `pass/fail/unclear/n-a` по каждому пункту рубрики |
| 3 | `substance.json` | сверка с `norms/` + живой MCP-поиск по Confluence |
| 4 | `slop.json` | маркеры неосмысленной AI-генерации + вопросы на понимание |
| 5 | `task-prompt.md` | обезличенный промпт задачи для внешней LLM |
| 6 | `report.md` | отчёт из json'ов, без LLM |

JSON-выходы валидируются jq по форме (`extract_json` снимает ```-заборы); невалидный ответ
роняет прогон с указанием файла. `workspace/` в gitignore.

## Разделение ответственности (что править при изменениях)

- **Что проверяем** — только `rubric/rubric.yaml`. Это единственный источник правды о
  проверках; промпты и отчёт строятся от неё. **id пунктов не переименовывать** — на них
  ссылаются `feedback/` и `substance.json`. Семантика полей описана в шапке файла.
- **Как проверяем** — `agents/reviewer.md` (роль и «железные правила»: `pass` только с
  дословной цитатой, догадка = `unclear` + вопрос автору, не выдумывать содержимое
  Confluence, ответы на русском) и `prompts/stage*.md` (формат каждого этапа, включая
  точные JSON-схемы ответов).
- **Против чего проверяем** — `norms/` (md-выгрузки стабильного ядра корп-доки; сейчас
  заглушки с FIXME). Учёт источников — `norms/INDEX.md`.

При изменении JSON-схемы в промпте синхронно править три места: `prompts/stageN-*.md`
(схема), jq-валидацию этапа и jq-сборку отчёта (этап 6) в `bin/review.sh`.

## Калибровка

После реального ревью — файл в `feedback/` по `feedback/TEMPLATE.md`: пропуски → правка
рубрики, враньё → правка промптов. Критерий готовности: на новом ADR ≥80% замечаний
архитектора без мусора.

## Конвенции

- Все тексты (промпты, комментарии, вердикты, отчёты) — на русском.
- Анти-галлюцинационные правила из `agents/reviewer.md` — принципиальны; не ослаблять их
  ради «более полных» ответов.
