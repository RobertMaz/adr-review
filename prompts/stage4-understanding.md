# Этап 4: проверка на неосмысленную генерацию

ADR разрешено писать с помощью AI — но автор обязан понимать каждую строчку. Твоя задача —
найти следы текста, который автор не понимает, и дать ревьюеру инструмент это проверить.

## Часть 1: маркеры генерации без понимания

Ищи в тексте ADR (каждый маркер — только с дословной цитатой):

- **противоречия между разделами** — числа в NFR не бьются с разделом нагрузки, в одном
  месте система синхронная, в другом асинхронная;
- **гладкая пустота** — обобщённый текст без единой привязки к конкретике компании:
  ни имён систем, ни реальных цифр, ни ограничений;
- **несуществующие сущности** — упомянуты системы, термины или «принятые у нас практики»,
  которых нет в тексте больше нигде и которые выглядят выдуманными;
- **числа и «best practices» из ниоткуда** — уверенные цифры и утверждения без источника
  и без вывода;
- **перепады стиля** — резкая смена терминологии, тона или глубины между секциями.

Маркер — это НЕ обвинение в AI-генерации. Формулируй как «похоже на неосмысленный текст,
потому что …». Нет маркеров — верни пустой список, не выдумывай.

## Часть 2: вопросы на понимание

Сформулируй 5–7 вопросов по самым нагруженным или подозрительным строчкам документа —
таких, на которые автор, писавший осознанно, отвечает мгновенно, а автор, вставивший
сгенерированное, поплывёт. Формат: «вы пишете X — что будет при Y?», «почему именно
такое значение?». Вопросы нейтральные, для устного разговора; привязывай каждый
к дословной цитате.

Ответ — один JSON-документ без обёртки:

```
{
  "markers": [
    {
      "marker": "<тип маркера одной фразой>",
      "quote": "<дословная цитата из ADR>",
      "explanation": "<почему это похоже на неосмысленный текст, одно-два предложения>",
      "confidence": "high | medium | low"
    }
  ],
  "comprehension_questions": [
    {
      "quote": "<дословная строчка ADR, к которой вопрос>",
      "question": "<вопрос автору>"
    }
  ]
}
```

## Текст ADR

{{ADR}}
